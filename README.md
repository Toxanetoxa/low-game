# LOW GAME

Браузерный файтинг для двух человек. Игровая логика и подключение написаны на TypeScript. В игре есть прыжок, удар, блок, раунды по 60 секунд и реванш.

[Играть в LOW GAME](https://toxanetoxa.github.io/low-game/)

GitHub Actions автоматически собирает и публикует игру на GitHub Pages после каждого push в `main`. Публикацию также можно запустить вручную через workflow **Deploy GitHub Pages**.

GitHub Pages размещает статическую игру. Для ставок нужен отдельно развёрнутый escrow-контракт: задайте его адрес и сеть в переменных репозитория `VITE_ESCROW_ADDRESS` и `VITE_ESCROW_CHAIN_ID`. Без них доступен кошелёк Base Sepolia, а ставки недоступны. Серверный CDP-кран запускается отдельно; его публичный HTTPS-адрес можно задать в `VITE_BASE_FAUCET_URL`. По умолчанию пополнение открывает OpenFaucet. Переменные применяются при следующей сборке.

## Запуск

```sh
npm ci
npm run build
open dist/index.html
```

`dist/index.html` содержит всю игру. Каждый игрок может открыть свою копию файла в браузере. Для разработки используйте `npm run dev`. Готовый файл также можно разместить на статическом хостинге.

Через Makefile доступны `make install`, `make dev`, `make build` и `make test`. Команда `make check` запускает проверку типов, ESLint и проверку форматирования. Все команды перечислены в `make help`.

## Проверка кода

ESLint использует конфигурацию `@antfu/eslint-config`, оформление задаёт Prettier.

```sh
npm run check
npm run lint
npm run format:check
```

Для автоматического исправления используйте `npm run lint:fix` и `npm run format`.

## Вход по никнейму

При первом запуске введите никнейм и нажмите **Войти в лобби**. Игра проверяет, свободен ли он среди игроков онлайн. При сравнении регистр букв и повторные пробелы не учитываются. Браузер запоминает имя и проверяет его снова при следующем запуске. Изменить имя можно перед созданием комнаты или подключением к сопернику.

Временные записи о занятых именах обновляются через общий MQTT-брокер, даже если игрок не создал комнату. Запись освобождается при закрытии вкладки и истекает при обрыве связи. Для входа требуется доступ к брокеру.

## Вызов игрока

В списке **Игроки онлайн** нажмите **Вызвать** рядом с никнеймом. Соперник может принять или отклонить приглашение. Принятый вызов запускает приватную дуэль по WebRTC. У игроков, которые уже ждут соперника или играют, отображается статус **Занят**.

## Открытые комнаты

1. Оба игрока открывают актуальную сборку игры.
2. Первый нажимает **Создать открытую комнату**.
3. Второй выбирает её в общем списке и нажимает **Войти**. После подключения начинается раунд.

В лобби видны комнаты, которые ждут второго игрока. Комната исчезает, когда хост принимает соперника или закрывает её. Если вкладка или сеть обрывается, запись автоматически истекает.

Список и сигнализация используют публичный тестовый MQTT-брокер EMQX через защищённый WebSocket. Запись комнаты содержит UUID, публичный никнейм и временный открытый ключ хоста. Браузеры шифруют параметры WebRTC для конкретного соперника с помощью Web Crypto, а игровой трафик идёт напрямую по WebRTC DataChannel. Для общего лобби откройте локальный HTML-файл, используйте localhost или статический хостинг с HTTPS.

Публичный брокер рассчитан на прототипы. Он координирует проверку имён между актуальными клиентами игры. [Публичный брокер EMQX](https://www.emqx.com/en/mqtt/public-mqtt5-broker)

## Закрытая дуэль по коду

Откройте **Закрытая дуэль по коду** в лобби.

1. Первый игрок нажимает **Создать комнату** и передаёт другу код приглашения, например в мессенджере.
2. Друг вставляет приглашение, нажимает **Присоединиться** и отправляет создателю комнаты код ответа.
3. Создатель вставляет ответ и нажимает **Подключить друга**. После установления связи начинается раунд. На публичном хостинге приглашение также можно отправить ссылкой.

Хост играет за RUST, гость — за VOLT. UUID входит в коды вместе с параметрами WebRTC. Браузеры получают параметры друг друга через обмен кодами, а игровой трафик идёт напрямую по WebRTC DataChannel. Браузер создателя комнаты рассчитывает состояние боя и отправляет его гостю.

Для подбора адресов через интернет по умолчанию используется публичный STUN Google. В одной локальной сети можно отключить этот параметр у обоих игроков. STUN помогает найти внешний адрес. В сетях, где прямое соединение блокируется NAT или файрволом, может потребоваться TURN-ретранслятор. В этой игре реализовано прямое подключение.

## Управление

У обоих игроков одинаковые клавиши.

| Движение | Прыжок | Блок | Удар |
| -------- | ------ | ---- | ---- |
| A / D    | W      | S    | F    |

Раскладка под ареной подсвечивает нажатые клавиши.

На телефоне лобби и бой открываются в альбомной раскладке. Кнопки движения и прыжка находятся слева от арены, блок и удар — справа. Если браузер поддерживает полноэкранный режим, кнопка **На весь экран** открывает его и запрашивает фиксацию альбомной ориентации. В портретном окне интерфейс поворачивается внутри страницы сразу при загрузке.

## Тестовые ставки

Оба игрока подключают кошельки в приватном матче. Создатель комнаты выбирает сумму и вносит её в контракт. Соперник проверяет сумму и вносит столько же. После двух подтверждённых взносов запускается один раунд со ставкой.

После боя каждый игрок выбирает итог и подтверждает его транзакцией. Два совпавших решения о победе начисляют оба взноса победителю. При ничьей или разных решениях каждый получает свою ставку обратно. Если второй взнос или подтверждение не поступило в срок, можно инициировать возврат. Начисленные средства выводит получатель через кнопку **Вывести**. Баланс подключённого кошелька виден рядом с никнеймом. Панель **Кошелёк и ставки** также показывает сумму к выводу. Через неё можно вернуться к сохранённым ставкам после выхода из комнаты.

```sh
npm ci
npm run test:escrow
npm run dev:escrow
```

Тест использует локальную цепочку в памяти. Команда `dev:escrow` открывает RPC на `http://127.0.0.1:8545`, разворачивает контракт и выводит значения `VITE_ESCROW_CHAIN_ID` и `VITE_ESCROW_ADDRESS`. Передайте эти значения при запуске `npm run dev`. Подключите Ethereum-кошелёк с тестовым балансом в этой сети. Для проверки двумя кошельками можно использовать два профиля браузера. Состояние локальной цепочки хранится до остановки процесса.

Для внесения ставок нужен указанный адрес контракта. Без него панель показывает баланс кошелька в Base Sepolia, а сумма к выводу недоступна. Поддерживаются локальная сеть с ID 31337 и Base Sepolia с ID 84532. Контракт проверяет взносы и голоса кошельков. Игровой результат рассчитывает браузер хоста, поэтому каждый игрок самостоятельно проверяет итог перед подтверждением.

Кнопка **Пополнить** рядом с балансом выдаёт 1 тестовый ETH в локальной сети с интервалом 60 секунд на адрес. Локальный кран запускается вместе с `npm run dev:escrow` на `http://127.0.0.1:8546/faucet`. При нестандартном порте укажите адрес из вывода команды в `VITE_LOCAL_FAUCET_URL`.

### Пополнение Base Sepolia

По умолчанию **Пополнить** открывает форму OpenFaucet внутри лобби. Скопируйте адрес подключённого кошелька, вставьте его в форму, запустите вычисление и подтвердите выдачу в форме. Баланс в лобби обновляется автоматически. [OpenFaucet для Base Sepolia](https://openfaucet.org/base-sepolia)

Для пополнения одной кнопкой можно подключить Coinbase CDP. Лобби само передаст адрес кошелька, покажет статус перевода и обновит баланс. Сервис пополнения запускается отдельно от игры. [Coinbase CDP Faucet API](https://docs.cdp.coinbase.com/api-reference/v2/rest-api/faucets/request-funds-on-evm-test-networks)

1. Создайте API-ключ в Coinbase Developer Platform. В корне игры создайте файл `.env.base-faucet` с `CDP_API_KEY_ID` и `CDP_API_KEY_SECRET`. Этот файл исключён из Git. [Настройка ключа CDP](https://docs.cdp.coinbase.com/api-reference/v2/authentication)
2. Запустите `npm run dev:base-faucet`. По умолчанию сервис доступен по `http://127.0.0.1:8547/faucet`, а браузер может обращаться к нему с localhost или 127.0.0.1 на портах 4000 и 5173.
3. Запустите игру с `VITE_BASE_FAUCET_URL=http://127.0.0.1:8547/faucet npm run dev`, подключите кошелёк в Base Sepolia и нажмите **Пополнить**.

Для статического хостинга задайте публичный HTTPS-адрес сервиса с путём `/faucet` в `VITE_BASE_FAUCET_URL` перед сборкой игры. Укажите точные адреса сайтов игры в `BASE_FAUCET_ORIGINS` на стороне сервиса через запятую. Для локального HTML-файла можно добавить в список значение `null`, которым браузер обозначает источник файла. Переменные `BASE_FAUCET_HOST` и `BASE_FAUCET_PORT` задают адрес и порт сервиса. Ключ CDP хранится в окружении сервиса.
